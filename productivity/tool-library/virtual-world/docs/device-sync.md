# 双端同步

手机和 PC 使用用户自己的 HTTPS WebDAV，同一台设备连接一个同步空间，手动同步。入口在侧栏「更多功能 → 双端同步」。本模块与原有 OSS 云端备份的配置、密钥、目录和恢复协议独立。

## 使用

1. 选择坚果云或其他 WebDAV。坚果云预填服务地址，账号和应用密码由用户填写。连接验证包含认证、目录访问、临时文件上传、读回和删除。
2. 建立同步空间，或加入另一端的同一空间。首次同步先展示本机和网盘的作品列表，不按名称覆盖作品。
3. PC 的「连接手机」生成接入二维码。二维码仅包含服务地址、账号、目录、空间标识；手机核对后单独填写应用密码。相机拒绝授权时可以手动配置。
4. 首次点击「预览首次同步」，核对数量后点击顶部「确认并开始首次同步」，对齐所选内容。完整清单默认折叠，确认按钮不会藏在长列表末尾。
5. 后续打开页面会先检查远端记录。默认「待同步」只列本机待上传、远端待下载和两端均修改的作品；已同步的完整清单在「同步范围」查看。
6. 「上传本机修改」只发布本机变化；「下载远端更新」只接收远端变化。若同一作品两端都有独立修改，单向操作暂缓该作品。顶部「全部采用远端」「全部采用本地」处理当前未完成项；每项直接显示「采用远端」「采用本地」，不再需要展开“查看并处理”。点击即明确选择该端完整版本并同步，包含该版本的文件删除；不再保留另一端的独立编辑。替换前的本机版本保留在“历史与恢复”中。单项选择只处理该项，暂停同步项不参与。
7. 操作中显示传输方向、作品与文件进度；完成后显示本次上传、下载和未完成项数量，不把无变化的全量作品计作同步数量。「检查远端更新」只更新远端记录，不传输作品或推进基线。

PC 与手机的“本地”都指当前操作设备，“远端”指其他设备已上传到网盘的版本。另一台设备下次同步时取回已采用的结果；尚未上传的编辑仍不可见。

同步短篇、剧本、长篇、素材库、技能库及分组的文本、结构、资源绑定和作品 AGENTS.md。长篇包含 `long/index.json` 引用的 `long/ledger/*.json` 章节账本；上传和接收均校验引用文件完整性。旧客户端漏传账本时，需要来源设备升级后重新上传。会话、追加事务、Agent 私有状态、全局模型配置、所有密钥、外观、封面和影音附件不进入同步内容。取消勾选只暂停本机参与。绑定资料必须可用，依赖资料未同步成功时相应作品暂缓。

## 安全与版本

- `src/core/device-sync` 是手机自包含的协议、严格 Schema、稳定序列化、版本向量、三方合并和接入码定义。PC 在 `packages/contracts/src/device-sync` 保存独立编译的镜像；运行时没有跨仓库依赖。
- `src/application/device-sync` 编排连接、预览、同步、收据、冲突与恢复。桌面镜像位于 `apps/desktop/src/extras/device-sync/engine`。
- `SyncTransport`、`SyncWorkspacePort`、`SyncMetadataStore`、`SyncCredentialStore` 分离网络、本地事务、非敏感元数据和安全凭据。
- 普通双向同步中，Markdown 只自动合并不重叠的行改动，同一位置不同插入也产生冲突。结构按稳定 ID 合并独立字段，双方改变顺序时保守提示。旧的冲突字段合并接口继续保留；页面的“采用远端/本地”明确采用所选端完整版本。
- 采用版本的请求携带所选作品 key 和方向；执行前重新读取本机与远端最新内容并校验，使用同一事务、历史、版本向量和收据路径。远端来源于其他设备的最新已上传版本；多台远端存在不同的并行版本时保留待处理项，不按时间或列表顺序覆盖。没有版本、内容损坏、结构不兼容或依赖未就绪时仍显示原因，不将缺失内容自动解释为删除。
- 本机保存带版本向量的基线历史，以共同祖先和版本向量决定合并，不用墙上时钟裁定覆盖。冲突、未确认删除、损坏或不支持的作品不推进基线，其余作品继续。
- 删除只来源于显式删除标记，目录读失败或作品缺席不作为远端删除。接收端确认删除前保留原版本；暂缓不把原文重新上传复活。
- 本机恢复版本、删除后的完整目录及云端提交历史首版均不自动清理，因此保留超过 30 天。恢复只写本机，下一次手动同步传播。
- 网盘上传成功与设备已取回分别显示。只有接收端处理了对应提交内容并发布收据，才显示已取回；页面注明最后检查时间。收据不包含未处理或排除的作品。本机与远端一致和另一端已取回分别显示；无法判断另一端尚未上传的编辑，检查失败也不宣称双端最新。

## 存储与网络

远端默认根目录 `DeepWriteSync`：

```text
spaces/<spaceId>/space.json
spaces/<spaceId>/objects/<hash前两位>/<packHash>.json
spaces/<spaceId>/devices/<deviceId>/head.json
spaces/<spaceId>/devices/<deviceId>/commits/<每256次提交分组>/<sequence>-<hash>.json
```

内容包和提交不可变，每台设备写自己的提交引用。上传内容读回验证后才发布提交；引用损坏时扫描该设备不可变记录。文件按哈希增量上传，小文件合包。支持 WebDAV Link 分页、请求节流、429/临时网关错误退避、超时、流式读取大小限制及取消。不完整或异常分页拒绝用于同步。服务商没有提供完整目录或分页时安全报错，不猜测缺失内容。

手机：`config/device-sync.json` 保存配置、基线与共同版本历史、接收记录、历史、待办。`config/device-sync-intent.json` 是待恢复的本地应用计划。书籍旁的 `.deepwrite-project-sync-identity.json` 保留桌面与手机项目、文档、人物、阶段和章节 ID 映射，识别已有桌面导入记录。短篇/剧本采用桌面 V4 交换清单，长篇采用现有桌面契约镜像。资源绑定保留在投影里；聊天不覆盖。

PC：Main 管理 WebDAV 和系统保护的凭据文件；Renderer 经独立受校验 Preload/IPC 调用，Core Utility 持有本地写入职责。同步写入加入 Core 命令串行屏障，检查实际版本，使用项目事务及独立恢复 intent。已有主入口中的备份桥接和服务装配已抽出模块。

手机应用密码使用 SecureStore `WHEN_UNLOCKED_THIS_DEVICE_ONLY`。PC 使用 Electron safeStorage，系统加密不可用或 Linux basic_text 时拒绝保存。Web 预览密码仅保存在内存。密码不进入 Zustand、普通 JSON、二维码、正文或错误日志。

## 增量同步性能修正（2026-09-13）

PC 与手机的手动同步先读取设备清单和 head 引用，引用未变时复用本机已验证的提交；正常检查不遍历提交历史。先按清单判断方向和变更，只对本次需要处理的作品加载候选内容；首次同步预览只读取清单，确认后才传输正文。已被新版本包含的旧候选不再下载。

下载按文件内容哈希复用对应作品的本机基线，只获取缺少的内容包。上传不再先下载其他待接收作品，单项采用版本只加载所选项。实际传输仍保留哈希、结构、写入版本与事务检查；新上传内容及提交仍读回确认后发布引用。显式采用版本继续重新读取其远端内容。日常同步不再把所有既有云端对象的健康检查作为前置步骤。

同步操作期间，进度轮询复用最近状态，结束后重新读取本机清单；不再每 1.5 秒重复导出全部作品。每次正式同步开始时仍读取本机当前内容，保证外部编辑可被发现。

新增请求计数回归覆盖 20 篇作品的双端同步：无变化时正文和提交内容传输为零，只读取两个设备 head（另有一次设备目录查询）；一篇正文变化时仅下载一个新增内容包。另覆盖首次预览不下载、上传跳过无关损坏内容、下载损坏内容保留基线及进度轮询不重复扫描。本测试使用内存 WebDAV，不代表真实网盘耗时；尚未重新打包或做真机网盘往返验证。

## PC 从远端初始化（2026-09-15）

PC 的「双端同步 → 从远端初始化」复用手机的初始化协议。普通下载因本机目录缺失、清单损坏或结构不兼容而跳过作品时，可以先在手机上传完整数据，再在 PC 选择该来源设备，点击「下载并预览远端数据」，核对数量后「用此版本初始化本机」。确认前不会替换作品；确认后清除旧列表中的项目并导入来源设备已上传的完整版本，包括替换暂停同步和本机独有的项目。

- 预览全量下载并验证每个文件、桌面作品契约与资料绑定。来源为空、文件缺失、结构不兼容或存在未合并的远端版本时整次拒绝，不先清空本机。初始化不能修复源端本身不完整的数据。
- 预览有效期为十分钟；确认时重查全部远端设备版本、本机内容指纹与同步配置。两端有新修改、预览过期或取消时，需要重新预览。预览和确认均经过编辑器保存门禁，生成期间不可执行。
- Core 在用户工作目录下独立的 `initialized-*` 目录写入并用原生存储打开、校验所有作品，再通过现有项目事务一次发布新注册表、注册表备份和初始化收据。所有 Core 命令先恢复未完成的发布事务。本机旧作品目录保持原样，不原地覆盖或删除；旧目录的注册记录及恢复说明位于用户数据目录 `device-sync-recovery/initialization-*`。
- Main 保留旧同步元数据，写入初始化 intent，等 Core 收据确认发布后更新基线。进程中断时根据收据恢复；Core 未提交时不推进基线。原网盘连接、模型配置、凭据不清除；不上传删除、不改动远端内容。新的本机同步历史从初始化后重新开始，旧历史保留于恢复目录中的元数据备份。
- 初始化完成后清理 Renderer 的目录、文档和长篇缓存，再重新加载工作台，避免旧活动长篇或同 ID 文档缓存遮蔽新内容。聊天记录不从远端导入；旧目录中的本机内容仍可重新打开恢复。

自动测试覆盖真实手机清单在 PC 的初始化、坏目录阻止普通下载后恢复、后续增量收敛、本机新修改、来源为空/缺文件/未合并、取消、预览失效、Core 发布中断和 Main 基线保存中断。界面用真实 Vue 组件和内存 IPC 验证浅色、深色、自定义强调色、18px 字号、紧凑窗口、来源切换、确认取消与保存刷新；验收截图位于 `dogfood-output/sync-initialization-review/`。这些验证未操作真实网盘或用户作品，不替代更新安装包后的双端真机验收。
