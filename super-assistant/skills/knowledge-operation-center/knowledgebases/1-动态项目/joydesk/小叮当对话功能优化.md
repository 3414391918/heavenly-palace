# 执行路径

1. **确认目标与基线。** 用户把目标分支从最初口误的 `feature/202610` 更正为 `feature/202609`，要求只优化「立即发送」的停顿、不调整样式。核对远端基线、工作区和当前桌面运行实例后，从最新 `origin/feature/202609` 建立独立开发分支，保留其他未跟踪文件。
2. **复现与定位。** 从待发消息的「立即发送」入口追到前端发送服务，确认旧路径先停止正在执行的任务，再等待发送锁释放并起新轮；将卡顿归因于这段任务切换，而不是排队消息本身。
3. **复用现有注入链路。** 检查 Electron `ai:inject-follow-up`、Gateway `chat.inject`、`PiLoopHost.injectFollowUp` 和安装的 Pi Agent 源码，确认 `agent.steer()` 已能将 `role: user` 消息放入既有 `steeringQueue`，Agent 循环会在后续模型请求前取出。
4. **修改前端并收紧边界。** 纯文本优先注入当前任务；无活动流或注入不可用时留在队列，图片与资源仍走完整新轮发送。处理「已提交」事件和注入响应的竞态，避免待发项重复出现。
5. **验证和启动。** 运行定向测试、Desk 类型检查及前端全量测试，记录通过项和既有失败项；提交代码并启动本地内场预发桌面端，让用户继续按实际交互验收。相关复现记录见仓库 `docs/bugs/repro/2026-10-23-immediate-follow-up-interrupts-turn.md`。
6. **核对插话进入后续推理。** 首次用 `sleep 30` 验证时，只看到工具执行结束，不能仅凭这次回复判断模型是否消费了插话。插话发生在工具运行期间，`PiLoopHost.pushOfficialUser → agent.steer` 将消息交给当前 Agent；工具结束后的下一次模型请求才会读取该消息。补齐插话事件和后续模型输出的回归，并在桌面端执行 `sleep 15` 期间发送插话，确认模型按插话要求回答；不能把注入接口返回 accepted 当作回答已完成。
7. **修复插话后的轮次显示。** `joydesk.user_message → apps/desk/frontend/src/stores/ai.ts` 会先追加用户插话；旧代码的 `aiMsgIndex` 仍指向插话前的助手气泡，而 `MessageList.vue` 把最后一条用户消息视为新轮起点，导致旧工具还在执行时，下方额外出现「正在思考」。新增 `streamContinuationBoundary.ts`：插话后等到新的思考、正文或 Typed Cell 起始事件，再创建助手续接气泡 `A1`；旧工具事件继续按工具／Cell ID 归属旧气泡 `A0`。插话和续接沿用当前 `requestId`，不启动第二个 Agent 请求。
8. **修复收尾快照与本地投影。** 旧 `ConversationProjectionService.ts` 遇到插话用户消息 `U1` 时将 `assistantIndexInTurn` 清零，却继续沿用原 `assistantMessageId=assistant:<runId>`，使 `A0` 和插话后的首条助手输出 `A1` 投影成同一个消息 ID。后续存储、去重和历史合并缺少区分两段输出的身份；模型已生成的续答因此可能在保存或重开时被覆盖、折叠。首轮桌面复验还发现 `ai.ts` 收尾按最初助手消息写快照，使 `A0.content_blocks` 也带上最终结论。修复后按当前 `steerSegment` 选中 `A1` 保存快照，投影给它独立的 `assistant:<runId>:steer:1` ID，同时继承原 `turnId/runId`，保留旧工具与 `A0` 的归属。
9. **修复云同步与历史合并。** `pending-message-collapse.ts` 原来主要按同一 `turnId` 折叠待上行助手消息，还可能把 `:steer:1` 认成过程步，导致本地可见的续答在同步或重开后丢失。去重键加入 `steerSegment`，过程步识别排除插话续答；前端 `conversationStore.ts` 的历史合并也先比较插话段号，再处理同轮折叠。桌面端切走并重开测试会话后，`A0 → 插话 → A1` 的顺序和正文仍一致。
10. **修复工作台资源遮住停止按钮。** `SearchInput.vue` 的运行态按钮由 `canSend` 控制；旧逻辑把分析工作台挂载的会话级 `operationContext` 当成本次输入草稿，空输入时仍显示发送按钮，停止按钮的 `!canSend` 条件因而失效。现在运行中仅按当前输入文字、图片、编辑器 chip 和引用判断能否发送插话；空草稿显示停止按钮。空闲时继续保留会话资源可发送的原有语义。
11. **修复结论交付后的误取消。** 结论已保存为 `runtimeStatus=completed`，但 `isLoading/isInStreaming/currentRequestId` 可能短暂残留；旧的 `stopConversationGeneration → aiStore.cancelStream` 会把再次点击停止记成「任务已中断」。现在先核对最后一条助手消息的完成态和 `completedRequestId === currentRequestId`；命中时调用 `conversationStore.clearCompletedConversationBusyState`，只清运行标记并将会话设为 `completed`，不取消流。若当前请求 ID 已换成新任务，仍可正常停止新任务。
12. **回归、提交和集成。** 为插话、消息列表、持久化、云同步和停止状态补充回归；桌面端真实插话后的回答及重开会话核对通过。相关修复提交为 `755e9bef8b`，与同一开发分支的 JoySpace 修复 `ed47902ba6` 一起合入并推送到 `feature/202609`，远端集成提交为 `a6983d4af3`。合并态推送门禁通过前端 15313 项、后端 9675 项测试及 Harness／协议契约检查。代码证据见仓库 `docs/bugs/repro/2026-10-23-immediate-follow-up-interrupts-turn.md`、`docs/bugs/repro/2026-10-27-steer-continuation-display.md` 和 `docs/bugs/repro/2026-10-27-stop-control-and-stale-cancel.md`。
