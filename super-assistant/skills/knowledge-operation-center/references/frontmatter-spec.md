# 审查状态与操作日志规范

本文件只定义模板无法编码、且本 skill 特有的规则：审查状态的 AI 行为语义、操作日志格式。

字段枚举值不在此复制。各模板的枚举如会议类型、需求状态、规范类型、待办类型等，以 `5-系统模板/` 模板 frontmatter 为唯一真相源，用 `obsidian template:read name="开发文档模板"` 动态获取。复制到本文件只会随模板演进而漂移，曾出现本文件把 `紧急等级` 写成 P0-P3、而模板该字段实际留空的错漏。

## 审查状态

审查状态是唯一跨模板通用字段，出现在每个模板里，且直接绑定 AI 行为，故在此定义，模板只能列选项、编不进 AI 该怎么做：

| 值 | 含义 | AI 行为 |
|---|---|---|
| 待审查 | AI 生成，未经人工审核 | 可创建，不可引用为可信上下文 |
| 已确认 | 人工审核通过 | 可引用为可信事实，禁止 AI 直接修改，走补丁流程 |
| 需重构 | 内容过时或结构不佳 | 提醒人类，可生成重构草案入待审查区 |
| 已归档 | 历史文档，不再活跃 | 不主动引用 |

状态流转：待审查经人类确认转已确认，已确认经人类归档转已归档；需重构经 AI 生成草案回到待审查。

审查状态使用文本属性保存单个枚举值，写入时用 `property:set name="审查状态" value="待审查"`，单值而非 `待审查|已确认|...` 选项串。

## 操作日志格式

`操作日志.md` 无对应模板，其格式以本节为唯一真相源。用无序列表而非表格：列表在大纲视图可折叠导航，且正文里的 `|` 不会像表格那样破坏列结构。字段用 `|` 作纯视觉分隔，不用 Dataview 内联属性，因为 `动作:: / 路径::` 这类 `::` 语法只对装了 Dataview 插件的人有意义，本库不依赖 Dataview，写入后是无效内容。只允许这一种格式，禁止表格、标题、复选框、自由文本，真实库中曾因混用五种格式导致无法阅读：

```text
- [YYYY-MM-DD HH:mm] 动作 | 路径 | 简述
```

用 `obsidian append file="操作日志"` 追加，禁止覆写。`操作日志.md` 顶部保留一行本格式示例作为锚点，供人与 AI 追加时对齐。

正确示例：

```text
- [2026-06-29 14:30] 更新 | 1-动态项目/2026-06-29 鉴权费用融合/鉴权费用融合.md | 合并补丁，补充费用路由时序
```

以下格式真实库中出现过，全部禁止：

- `| 2026-06-29 | AI | 演化 | ... |`，表格格式，污染大纲
- `## [2026-06-29] 重构`，标题格式
- `- [x] 2026-06-29 深度整合开发文档`，复选框加自创动作
- `- [2026-06-29] 动作:: 更新 | 路径:: ...`，Dataview `::` 语法，本库不用 Dataview

### 动作枚举

仅此 6 个，禁止自创。真实库中曾出现 晋升、演化、整合、重构、重写、深度整合、补丁、沉淀、创建、修改、完善文档 等十余种自创动作，一律不允许。所有工作流动作必须映射到下表之一：

| 值 | 含义 | 由哪些工作流产生 |
|---|---|---|
| 新建 | 创建新文件 | 沉淀、答案回填、巡检或演化生成草案 |
| 更新 | 修改现有文件内容 | 增量更新合并、演化重写正文、标记需重构 |
| 移动 | 文件在目录间移动 | 晋升，待审查到正式目录 |
| 归档 | 标记已归档并移入历史归档 | 项目完成、废弃归档 |
| 废弃 | 文档不再维护，不移动时用 | 演化中弃用旧结论 |
| 关联 | 补充双链引用关系 | 巡检补链、演化交叉引用 |

若某动作难以归类，优先用 更新。绝不为 晋升、整合、重构 等语义新造动作词，那些是工作流名，不是 log 动作。

### 查询

日志也必须经 CLI 读取，禁止直接 grep vault 文件：

```bash
obsidian read file="操作日志"                  # 读全量日志
obsidian search:context query="更新" limit=20   # 按正文关键词查某类动作
```

## 属性写入类型速查

`property:set` 的 `type=` 必须与 Obsidian 配置的属性类型一致，否则形态错乱。`scripts/create_note.sh` 已自动匹配，手动写入时参照：

- `aliases`、`tags` 用 `type=list`
- `创建时间`、`修改时间`、`提测时间`、`上线时间` 用 `type=datetime`
- `是否完成` 用 `type=checkbox`
- `审查状态`、`需求类型`、`需求状态`、`会议类型`、`待办类型`、`规范类型` 等枚举用 `type=text`，枚举保存为文本
- 其余用 `type=text`

CLI 写入的具体陷阱，包括 datetime 必须带 T、list 多值一次写入、模板占位串必须覆盖，见 [gotchas.md](gotchas.md)。
