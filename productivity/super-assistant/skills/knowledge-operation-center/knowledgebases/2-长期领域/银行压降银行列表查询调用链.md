# 银行压降银行列表查询调用链与 DropBankInfo 结构

> [!info] L2 接口经验
> 银行压降域的调用链与返回结构详解。域总览见 [[银行压降域知识总览]]，代码定位见 [[银行压降代码定位与日志关键字]]。

## 接口信息

- **方法全名**：`com.jd.bdp.mrc.market.reduction.center.duty.MoloDropBankBiz#discountDropBankQueryBankList`
- **上游入口**：收银台 `JdpayCashierServiceImpl#getDiscountInfo`、结算页 `marketing.mall.discount` 侧营销策略链
- **所属应用**：market-reduction-center（非营销压降中心）

## 调用链（收银台实证）

```
JdpayCashierServiceImpl.getDiscountInfo
  → nonMarketingMoloDropBankList-Pool-N 线程池异步
    → MoloDropBankBiz.discountDropBankQueryBankList
      → flowExecuteEngine（JSF，alias/timeout.flowExecuteEngine 配置）
        → DropBankInfo 列表 → discountDropBankMap
          → nonMarketingPrizeInfo.dropBankInfoList（前端过滤银行卡）
```

策略链位置：`ExternalPromotionStrategyEnumV2` 中 `moloDropBankStrategy` 排在首位，其后为 bankPointStrategyV2、intelligentMoloStrategy、returnSortStrategy。

## 关键入参（摹略 flowKey）

- flowKey = `F787113210841219191106381`
- tradeAmount（订单金额）、pin、bindCardNum（绑卡数）、merchantNo（如 JD_APP_00）
- appClientSource（如 JDPAY_JD_APP）、cashierSource（如 jdpay_sdk_jdmall）

## DropBankInfo 返回结构

- **usableCreditCardCodes / usableDebitCardCodes**：白名单（可参与活动的银行）
- **blackCreditCardCodes / blackDebitCardCodes**：黑名单（不可参与）
- **needDropAwardIds**：需要压降的活动 ID 列表
- **dropCreditCardCodes / dropDebitCardCodes、dropType**

处理规则：**白名单与活动可用银行取差集后返回活动列表**；黑名单按启用状态决定 `canUsePayToolList` 是否剔除。支付压降 3.0 场景返回 canUsePayToolType + cutCardList。

## discountDropBankMap key 格式

`活动ID_ExpressCardPI-银行-卡类型-标识`，value 为压降明细，前端据此过滤展示银行卡。

## 关联模块

- **C018 无营销文案**：molo 压降查询返回 `DropResultType.SUCCESS`（**空列表也算成功**）是 C018 出文案的前置条件之一。
- **-1 卡/1 分购**：getNonDropBankResource 替换非压银行资源位，shortPrizeDesc 改为"限时仅需¥0.01"。
- **大支付调控**：与压降查询串行，要求 10ms 内响应。
