# 银行压降代码定位方法与日志关键字

> [!info] L2 代码定位经验
> 银行压降域的代码路径与日志关键字速查。域总览见 [[银行压降域知识总览]]，调用链与返回结构见 [[银行压降银行列表查询调用链]]。

## 接口信息

- **方法全名**：`com.jd.bdp.mrc.market.reduction.center.duty.MoloDropBankBiz#discountDropBankQueryBankList`
- **所属应用**：market-reduction-center（非营销压降中心）

## 代码定位路径

- **业务实现**：`market-reduction-center` 应用 `duty` 包下 `MoloDropBankBiz`
- **策略入口**：`ExternalPromotionStrategyEnumV2` 枚举中 `moloDropBankStrategy`（策略链第一位）
- **收银台侧调用**：`JdpayCashierServiceImpl#getDiscountInfo` 内通过线程池 `nonMarketingMoloDropBankList-Pool-N` 异步调用

## 日志关键字（按定位顺序）

| 日志关键字 | 用途 |
|------------|------|
| `查询molo压降银行列表` | MoloDropBankBiz 查询入口，含完整入参（flowKey、tradeAmount、pin、bindCardNum、merchantNo 等） |
| `discountDropBankQueryBankList` | 方法级定位 |
| `Parse molo result` | flowExecuteEngine 返回结果解析，DropBankInfo 原始内容 |
| `discountDropBankMap` | 压降结果 map 装配，key 格式 `活动ID_ExpressCardPI-银行-卡类型-标识` |

## 配置与监控项

- JSF 别名：`jsf.alias.flowExecuteEngine` / `jsf.timeout.flowExecuteEngine`
- 线程池：`nonMarketingMoloDropBankList-Pool-N`（收银台侧异步）
- UMP 监控项覆盖压降查询成功率与耗时

## 定位流程建议

1. 先拿交易 trace，在 market-reduction-center 日志中搜 `discountDropBankQueryBankList`
2. 找到入参后核对 flowKey 与 merchantNo/appClientSource 是否符合预期
3. 看 `Parse molo result` 确认摹略返回的 DropBankInfo（注意**空列表也算成功**，不代表压降未生效）
4. 再到收银台/结算页日志搜 `discountDropBankMap` 确认前端过滤结果
