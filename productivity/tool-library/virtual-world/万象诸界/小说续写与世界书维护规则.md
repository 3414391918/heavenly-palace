## 1. 项目边界

本项目只包含以下三类内容：

- 本文件 `AGENTS.md`；
- 酒馆平台导出的世界书 JSON；
- 已完成的小说章节。

世界观、人物设定、修炼体系、时间线、人物当前状态、关系变化、知识边界、物品与能力、伏笔及其他一切小说信息，都统一维护在世界书 JSON 中。

不得另行创建世界书备份、人物状态表、时间线文件、伏笔表、修改记录、审校报告、创作计划或长期保留的临时分析文件。确因程序安全写入产生临时文件时，完成后必须删除。

项目使用 Git 管理版本：

- 开始修改前先检查工作区，识别用户已经存在的未提交改动；
- 不自动提交；
- 不执行 `reset`、`checkout`、`restore`、`clean`、`revert` 等可能覆盖现有改动的操作；
- 不修改 `AGENTS.md`，除非作者当前任务明确要求；
- 原则上只新增下一章并修改世界书 JSON，不改动无关文件。

## 2. 核心职责与任务闭环

每次收到续写任务后，必须直接完成以下闭环：

1. 读取并理解世界书与已有章节；
2. 建立下一章开始时的准确故事状态；
3. 在内部完成章节结构与因果规划；
4. 创作并保存完整的下一章；
5. 对正文进行结构、连续性和行文审校，并直接修正；
6. 提取本章最终造成的全部事实与状态变化；
7. 原地优化并更新同一个世界书 JSON；
8. 验证正文、世界书和 Git 差异；
9. 简要汇报结果。

不得只输出分析、计划、建议或待确认事项。非关键细节缺失时，应依据现有文件作出最合理的判断并继续执行。

若存在无法安全解决的核心冲突，应先完成不受影响的部分，采用最保守的处理，不得擅自重写核心设定，并在最终汇报中指出。

每完成一章都必须检查并同步世界书。即使没有新增大型设定，也必须至少同步剧情进度、章末人物状态、时间线、关系、知识边界、物品资源和伏笔变化。

## 3. 内容权威、正史边界与冲突处理

不同问题分别以不同来源为准：

- 作者在当前任务中的明确要求拥有最高优先级；
- 已经发生的事件、人物作出的选择、已公开的信息和既成结果，以已完成章节为准；
- 世界运行规则、人物长期设定、修炼体系及世界书中维护的当前故事状态，以世界书 JSON 为准；
- 当前任务中的剧情概要只规定下一章的方向、关键事件和预期结果，在写入最终正文前不视为已经发生。

若世界书中的动态状态落后于最新章节，以最新章节已经发生的事实为准，并在本次任务中修正世界书。

若已完成章节与世界书核心规则存在旧冲突，不得通过无声修改核心规则或旧章节来掩盖。应优先寻找能够兼容双方的最小解释；无法兼容时，维持已发生事实与核心规则的现状，在后续正文中避免扩大冲突，并在最终汇报中说明。

原则上不得修改已完成章节。只有作者当前任务明确要求修订旧章时，才可改动旧章正文。

以下内容默认属于保护级设定：

- 世界起源与底层法则；
- 修炼体系根本原理；
- 大境界表现力上限；
- 主角和核心人物的身份、血脉、核心能力与既定命运；
- 核心势力真实立场；
- 主线谜底、重大转折和最终结局；
- 世界书中被标记为锁定、核心、不可修改或同等含义的内容。

除非作者当前任务明确要求，否则不得为了迁就新章节而修改保护级设定。普通设定可以在有充分依据时澄清、补充或优化，但必须遵循影响最小原则，不能用“补充说明”的名义改变其本质。

## 4. 创作前读取与状态建立

开始写作前必须：

- 使用 JSON 解析方式读取世界书，先识别真实顶层结构、条目容器、标识规则、字段类型和平台元数据，再定位本章相关内容；
- 找出世界书中承担当前状态、时间线、人物信息、关系、物品、伏笔等功能的现有条目，优先沿用，不重复建立同类条目；
- 检查章节的排序、命名、格式和保存方式；
- 依据章节编号、标题和正文内容判断最新章节，不以文件修改时间代替章节顺序；
- 重点阅读最近三至五个完整章节，并检索本章人物、地点、势力、功法、法宝、关系、秘密和伏笔在更早章节中的相关内容；
- 从现有正文中归纳叙事人称、视角、叙事距离、段落节奏、对话习惯、语言风格、章节长度和标题格式。

正式创作前，必须在内部确认下一章的起点状态：

- 当前时间、地点及距上一事件的时间间隔；
- 登场人物的位置、境界、能力、伤势、精神状态和资源；
- 物品、功法、法宝的持有者、状态及可用条件；
- 人物当前目标、立场、关系、承诺和矛盾；
- 每个重要人物已经知道、不知道、误解或刻意隐瞒的信息；
- 正在推进的主线、支线、冲突、伏笔和未解决问题；
- 本章结束时应当发生的关键状态变化。

如果章节位置是目录，按现有规则创建下一章文件；如果是持续汇总正文的单个文件，则沿用原格式追加下一章。

## 5. 内部章节规划

正式写正文前，应在内部把剧情概要细化为必要的场景链，但不得另行创建规划文件，也不得停在规划阶段等待确认。

每个场景至少应明确：

- 视角人物；
- 场景目标；
- 阻碍或对立力量；
- 冲突升级；
- 转折；
- 人物选择；
- 代价；
- 信息释放与隐藏；
- 场景结束后的状态变化；
- 与下一场景的因果联系。

场景之间应尽量形成“因为前一事件，所以人物采取行动；但是出现阻力；因此人物改变选择并造成下一结果”的因果链，避免只用“然后又发生一件事”机械串联。

敌人、竞争者、宗门、家族、制度或其他对立力量必须拥有自身目标，并根据其掌握的信息和可调用资源主动反应，不得只等待主角推动剧情。

新增人物、地点、功法、法宝、势力或概念，必须至少承担推进情节、塑造人物、强化主题、建立规则、制造阻碍或形成伏笔中的一种功能。不得只为显得宏大而堆砌设定。

## 6. 正文创作要求

将剧情概要写成完整小说章节，而不是剧情摘要、流水账或机械扩写。必须保留作者给出的关键剧情方向和结果，同时补足合理的场景、因果、动作、对话、心理变化、阻碍、代价和过渡。

章节编号、标题、文件名、保存格式和叙事方式均沿用现有章节。作者未指定字数时，以最近三个完整章节的通常篇幅为基准，避免无理由大幅偏离。

创作时必须遵守：

- 人物行为符合其性格、立场、目标、能力、关系、处境和已知信息；
- 人物不得突然知道不可能知道的内容，也不得无故忘记已有能力、物品、经历或承诺；
- **人物知识边界交叉检查**：当角色A提及角色B的体质、能力、法宝、换装等私人信息时，必须确认A从何处得知该信息。除非剧情中明确发生过A被告知或A亲眼目睹并理解了该信息，否则A不得知道B的未公开信息。尤其注意：老板娘、路人、拍卖会参与者等非亲密角色，通常不知道主角的特殊体质、修炼方式或换装能力。不能在对话中让这些角色说出他们不可能知道的信息。；
- 重要立场、关系和情绪变化必须有可见铺垫、触发原因和行为后果；
- 修炼、战斗、境界、功法、神通和法宝表现不得突破世界书限制；
- 所有超常表现都必须能追溯到既有能力、特殊条件、策略、环境、协助或代价；
- 越境行为必须符合世界书允许的边界，并承担与收益匹配的消耗或后果；
- 战斗中的位置、距离、动作顺序、攻击范围、伤势和资源消耗必须清楚连贯；
- 时间、路程、恢复速度、物品归属和人物位置前后连续；
- 世界观信息通过行动、对话、环境、制度和后果自然呈现，不直接复制世界书进行大段说明；
- **世界设定对词汇选择的约束**：世界书中的底层设定约束着所有角色的用语和身份表述。例如洪荒界「没有凡人，统称为修士」，则任何角色在自称或描述他人时，不得使用"凡人""普通女子""普通人""一介平民"等暗示存在非修士人口的词汇。角色自述应当使用"普通修士""低阶修士""散修"等符合世界设定的替代词。创作前须遍历世界书中的底层设定，识别所有可能影响日常用语的约束条件；
- 严格保持既有叙事视角，不让视角人物直接获知其无法感知的信息；
- 不同人物应保持不同的用词、语气、身份意识和言外之意；
- 对话不得重复双方都知道的设定，也不得变成作者说明书；
- 保持现有章节的叙事声音，不直接模仿或复制任何具体作家的标志性表达。

行文应避免：

- 因果不清的华丽描写；
- 无意义重复和过度解释；
- 连续堆叠形容词、比喻和四字词语；
- 所有人物使用同一种说话方式；
- 空泛抒情、强行升华和无关哲理；
- 模板化悬念、频繁视角跳转和“他不知道的是”式生硬揭示；
- 频繁使用“仿佛”“似乎”“不由得”“心中一凛”等填充表达；
- 用模糊异象掩盖战斗逻辑；
- 明显的 AI 腔、大纲扩写感和段尾总结习惯。

## 7. 正文审校

初稿完成后必须进行三轮检查，并直接修改正文，不得只列出问题。

### 第一轮：结构、因果与节奏

检查：

- 是否完成本章关键剧情；
- 每个场景是否具有明确作用；
- 事件之间是否有原因、选择和后果；
- 是否存在强行巧合、缺失步骤、铺垫不足或无效场景；
- 对手是否作出了合理反应；
- 情绪、冲突和信息释放是否逐步推进；
- 章节结尾是否由本章结果自然引出后续。

### 第二轮：连续性与设定

检查：

- 时间、地点、路程和事件先后；
- 人物境界、能力、伤势、资源、记忆、目标和知识边界；
- 人物关系、立场和情绪变化；
- 功法、法宝、物品数量、归属、损坏和消耗；
- 世界规则、势力关系、社会制度和境界表现力；
- 名称、称谓、外貌、场景空间和专有名词；
- 叙事人称、视角边界、人物声音和风格一致性。
- **角色知识边界专项检查**：遍历所有对话与非视角叙述，确认每一条被提及的他人信息（体质、能力、法宝、换装、来历等）都有可信的来源——该信息是否已被公开、是否被该角色亲眼目睹并理解、是否由当事人亲自告知。老板娘、拍卖会参与者、路人等非亲密角色，不应知道主角的未公开信息。若发现信息泄露无来源，修改相关对话或叙述。；
- **世界设定对词汇的影响检查**：检查所有角色自称、他称、描述性旁白中是否使用了与世界书底层设定矛盾的词汇。例如洪荒界「没有凡人」，则所有角色不得自称或被称为"凡人""普通女子""普通人""一介平民"等，应改为"普通修士""低阶修士""散修"等符合设定的表述。检查范围包括人物对话、内心独白、叙事旁白在内的全部正文。；

### 第三轮：行文润色

检查并修正：

- 病句、歧义、重复和逻辑跳跃；
- 生硬转场和动作空间不清；
- 对话节奏与人物区分度；
- 描写密度和段落节奏；
- 情绪缺少过程或过度解释；
- 辞藻堆砌、模板表达和风格漂移。

优先进行有针对性的局部修订，避免无必要地反复整章重写，导致原有风格和已经正确的细节发生漂移。

正文审校完成之前，不得更新世界书。

## 8. 章节变化量提取

正文最终确定后，先在内部比较本章开始状态与章末状态，提取本章变化量，再修改世界书。

至少检查：

- 新增或被正式澄清的世界事实；
- 剧情时间、地点和进度变化；
- 人物位置、境界、伤势、精神、目标和立场变化；
- 人物关系与知识边界变化；
- 新获得、失去、消耗、损坏或转移的功法、能力、法宝、物品和资源；
- 势力、局势和社会关系变化；
- 已发生的重要事件及其因果影响；
- 新埋下、被强化或已回收的伏笔；
- 新产生、继续推进或已经解决的故事线；
- 对下一章仍然有效的限制、承诺、风险和悬念。

只有最终正文中真实发生或正式确立的内容，才可以作为本章事实写入世界书。剧情概要中尚未写入正文的未来事件，不得标记为已经发生。

临时气氛、一次性修辞、瞬间情绪和没有后续作用的细节，不应自动升级为长期设定。

## 9. 世界书更新与优化

每完成一章，都必须原地修改同一个世界书 JSON，不创建备份文件。

### 9.1 静态设定与动态状态

虽然静态设定和动态状态都存放在同一 JSON 中，但必须在语义上清晰区分：

- 静态设定描述世界、人物、力量和制度通常如何运行；
- 动态状态描述当前剧情节点下人物、物品、关系、时间线和故事线处于什么状态。

动态状态条目应反映本章结束时仍然有效的最新状态。旧的可变状态应被更新或替换，不能与新状态并列保留在同一活跃条目中造成矛盾。

已经发生的重要历史事件应以简洁的事件记录或既有时间线结构保留，而不是因为当前状态更新而被完全抹去。

角色私下掌握的秘密只能更新到对应角色的知识边界中，不能因为世界书记录了该事实，就默认所有人物已经知道。

如果世界书已有专门的当前状态、时间线、人物状态或伏笔条目，应更新这些既有条目；只有确实缺少承载位置时，才可按照现有结构新增条目。

### 9.2 允许的操作

允许根据本章事实和相关条目的实际质量执行：

- **增加**：新增后续会继续使用的正式设定、实体、状态或故事线；
- **修改**：同步变化、澄清模糊内容、修复明确错误或补足必要限制；
- **拆分**：将混合多个独立主题、过长或难以准确触发的条目拆成主题单一的条目；
- **合并**：合并实质重复、边界重叠且合并后更利于检索的条目；
- **移动**：在现有分类或结构中调整放置位置；
- **删除**：删除完全重复、明确错误、已经失效或被正式替代的内容。

拆分时必须完整迁移有效信息，并同步调整关键词、关联和平台配置。合并时必须消除重复但保留所有仍有效的限制条件。删除前必须确认其中没有仍需保留的信息，也没有产生悬空关联。

世界书维护以本章相关条目和直接受影响条目为主要范围。可以顺带修复读取过程中发现的明显重复或错误，但不得借一次续写任务进行与本章无关的大规模重构。

### 9.3 条目质量与触发效果

更新后的条目应做到：

- 一个条目围绕一个清晰主题；
- 内容简洁、准确、信息密度高；
- 设定、限制、当前状态和关联关系表达明确；
- 关键词优先使用稳定名称、别名和确有区分度的相关词；
- 避免使用过于宽泛、常见、容易误触发的关键词；
- 拆分条目后，关键词应按主题重新分配；
- 不把整章正文、长篇复述或无复用价值的描写塞入世界书；
- 不随意把普通条目改成常驻触发，也不随意改变选择性、概率、深度、位置等触发机制；
- 不因当前章节写作方便而削弱世界底层规则、境界上限或人物核心设定。

### 9.4 JSON 结构与平台元数据

必须保持酒馆世界书现有 JSON 结构和平台元数据，不得假定世界书使用固定版本或固定字段。

不得擅自更换：

- 顶层结构；
- 条目容器类型；
- 字段名称；
- 字段类型；
- 平台专用数据格式。

已有的以下内容必须保持有效：

- 对象键、ID、UID或其他标识；
- 条目排序；
- 启用或禁用状态；
- 主要与次要关键词；
- 常驻、选择性、概率等触发配置；
- 插入位置、深度、角色、扫描范围及其他平台元数据；
- 条目之间已经存在的关联。

新增条目时，应仿照当前文件中的真实结构和标识规律，生成不冲突的标识。如果同一标识同时存在于对象键、`id`、`uid` 或其他字段中，应按现有约定保持一致。

除非为修复明确问题，不得更改与内容更新无关的元数据。

## 10. JSON 安全写入与 Git 验证

修改 JSON 时必须使用结构化解析与写入方式，不得依靠正则表达式直接替换复杂 JSON 内容。

写入时应尽量保持原文件的：

- 字符编码与 BOM 状态；
- 换行符；
- 缩进；
- 键顺序；
- Unicode 表示方式；
- 条目顺序。

不得为了格式美化、字段排序或代码风格统一而重新序列化整个文件，造成大面积无意义差异。

若原始 JSON 在修改前就无法解析：

- 先定位错误；
- 只有在修复方式明确且不会改变内容含义时，才可修复后继续；
- 不得猜测性重建或覆盖整个世界书；
- 无法安全修复时，保留原文件，完成能够安全完成的正文工作，并在最终汇报中说明。

写入后必须重新解析并检查：

- JSON 语法有效；
- 顶层结构和主要字段类型未被破坏；
- 对象键、ID、UID等标识在适用范围内不存在冲突；
- 没有意外丢失条目；
- 没有悬空关联或明显失效的关键词配置；
- 本章涉及的状态、时间线、关系、知识边界、物品资源和伏笔均已同步；
- 保护级设定没有被无授权改变。

最后使用 `git status` 和 `git diff` 复核：

- 新章节是否正确新增或写入；
- 世界书修改是否与本章事实一致；
- 是否出现整份 JSON 无意义重排；
- 是否误改用户原有改动或无关文件；
- 是否残留临时文件、占位符或调试内容。

## 11. 完成标准与最终汇报

只有同时满足以下条件，任务才算完成：

- 已读取本章需要的世界书和历史章节；
- 已准确承接最新章节状态；
- 已完成并保存正式下一章；
- 关键剧情符合作者概要；
- 人物动机、知识边界和行为成立；
- 时间、空间、伤势、能力、物品、关系和境界连续；
- 已完成三轮正文审校并修正问题；
- 已提取章节变化量；
- 已原地更新并优化世界书；
- 世界书反映章末最新动态状态及重要历史事件；
- 更新后的 JSON 能够正常解析，结构和标识有效；
- Git 差异范围正确，没有覆盖无关改动；
- 没有创建项目边界之外的持久文件。

最终回复保持简洁，只需说明：

- 新章节编号、标题、保存位置和字数；
- 本章推进的核心事件；
- 世界书增加、修改、拆分、合并、移动或删除了哪些相关条目；
- 动态状态、时间线、关系、知识边界、物品资源和伏笔的主要同步结果；
- JSON 验证和 Git 差异检查结果；
- 尚无法安全解决的冲突或需要作者注意的问题。

不要在最终回复中重复粘贴整章正文，也不要额外创建汇报文件。
