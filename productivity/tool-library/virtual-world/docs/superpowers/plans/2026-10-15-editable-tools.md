# 可编辑工具与手动创作界面 Implementation Plan

**Goal:** 将创作编排交给外部 Agent，保留手动界面、自定义模型和声音创建，以工作目录中的可编辑工具提供创作空间管理能力。

**Architecture:** 工具以 `工作目录/tools/<id>/tool.json` 与说明、脚本文件组成，首次初始化内置工具后保留用户修改。工具管理只读写文件，不执行脚本；外部 Agent 通过独立 Node CLI 调用共享小说文件引擎，应用无需运行。现有 `deepwrite.json`、`long/` 和技能/素材目录格式保持兼容。

**Tech Stack:** Electron、Vue、Zod、Node.js、现有项目事务与领域模型。

## 1. 可编辑工具目录

- [x] 定义工具元数据、文件快照、关联关系及 list/read/save/create/delete IPC 契约。
- [x] 实现工作目录工具存储；文件路径限制在工具目录内；拒绝符号链接与越界路径；保存使用内容哈希防止覆盖外部新修改。
- [x] 默认工具仅首次安装，之后不覆盖修改或恢复用户删除的工具；解析失败的工具单独报告，不阻断其它工具。
- [x] 编辑页展示工具文件、说明、代码和元数据；支持新增文件与工具、保存、重新读取、复制绝对路径，以及关联和反向引用跳转。

## 2. 外部 Agent 工具

- [x] 生成独立小说引擎的可读 JavaScript，复用原有结构操作、文档写入、提交章节和连续性清理；不依赖 Electron、IPC 或本机注册表。
- [x] 创作空间 CLI 提供 schema、create、index、read、search、preview、apply、writeChapter、commitChapter、deleteLedgerCommit、角色档案与形象目录操作。
- [x] 创作上下文工具通过绝对路径读取小说约束、技能与素材，按需加载正文；整合原资料管理方法，并调用创作空间 CLI 获取索引。
- [x] 创作工具使用 Markdown 编排上下文、设定对齐、写作、检查和连续性提交，明确调用另外两个工具。
- [x] 验证应用关闭时，复制出的工具仍能创建、读取、编辑小说并保持文件格式与关联一致。

## 3. 手动界面
