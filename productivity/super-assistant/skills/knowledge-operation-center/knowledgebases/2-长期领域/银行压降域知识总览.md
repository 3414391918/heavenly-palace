# 银行压降域知识总览

> [!info] L1 业务域经验（聚合器）
> 本页是银行压降域的入口聚合器，只存指针、检索关键词与易错点。详细调用链与代码定位见 L2 接口经验。

## 域标识

- **业务域名称**：银行压降
- **同义词**：压降银行、molo 压降、摹略压降、银行调控、银行卡压降、发卡行限制
- **典型问句**：
  - "什么是银行压降？"
  - "收银台为什么有的银行卡不参加优惠？"
  - "用户反馈某银行卡没有立减/优惠，怎么排查？"
  - "discountDropBankMap 里的 key 是什么格式？"
- **关联业务域边界**：压降按发卡行维度限制；大支付调控按支付金额维度调控，两者串行执行但机制不同，勿混淆。

## 业务定义

银行压降是京东结算页/收银台按**发卡行维度**限制部分银行卡参与营销优惠的风险与成本控制机制，由摹略（MOLO）平台配置的决策集驱动执行。

核心调控集：

| 调控集 | 含义 |
|--------|------|
| mbc | 银行卡类型档位（A-G 费率档） |
| mbp | 利润率等级 |
| mbs | 利润率数值，用于常用卡加磅压降 |

## 核心概念

| 概念 | 说明 |
|------|------|
| 摹略平台 | 决策集配置与压降策略执行方，flowKey=F787113210841219191106381 |
| DropBankInfo | 压降结果结构：白名单（usableCardCodes）/ 黑名单（blackCardCodes）/ needDropAwardIds / dropType |
| 白名单规则 | 白名单与活动可用银行取差集后返回活动列表 |
| 黑名单规则 | 按启用状态决定 canUsePayToolList 是否剔除 |
| discountDropBankMap | 前端过滤用 map，key 格式：`活动ID_ExpressCardPI-银行-卡类型-标识` |
| 策略链位置 | ExternalPromotionStrategyEnumV2 中 moloDropBankStrategy 排第一位 |

## 场景清单

- 收银台（getDiscountInfo，jdpay_sdk_jdmall）
- 结算页（marketing.mall.discount 策略链）
- 商详页（非万象/万象分流）

## 排查路径（四步）

1. 拿交易 trace，在 market-reduction-center 日志搜 `discountDropBankQueryBankList`
2. 核对入参：flowKey、merchantNo、appClientSource 是否符合预期
3. 看 `Parse molo result` 确认摹略返回的 DropBankInfo
4. 到收银台/结算页日志搜 `discountDropBankMap` 确认前端过滤结果

## 易错点

- **摹略返回空列表也算 DropResultType.SUCCESS**，不代表压降未生效——C018 出文案以此为前置条件。
- 压降查询走线程池 `nonMarketingMoloDropBankList-Pool-N` 异步，与大支付调控串行，要求 10ms 内响应。
- 压降影响的资源位处理：getNonDropBankResource 替换非压银行资源位（-1 卡/1 分购联动）。
