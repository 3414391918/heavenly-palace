# 执行路径

1. 调用 `functions.exec` 中的 `exec_command`，用 `rg --files` 找到 DeepWrite 的 `AGENTS.md`、`README.md` 和长篇创作相关模块；用 `cat` 阅读项目约束与可视化技能说明，确定以 Mermaid 时序图呈现创作调用链。
2. 用 `rg -n` 搜索世界观、人物、剧情、正文、连续性账本及章节提交的实现，再用 `sed` 阅读 `long-workspace/ids.ts`、`long-workspace/agents.ts`、长篇工作区类型和项目初始化代码，确认长篇创作由同一长篇智能体跨五个阶段工作，以及七类世界观和人物档案等初始结构的来源。
3. 用 `python3` 读取“万象诸界”的长篇项目索引，核对真实创作空间中世界观、人物和章节的结构；将初始化的容器与后续由智能体或作者写入的实际内容区分开。
4. 用 `sed` 阅读 `prompts-long.ts`、`long-agent-tools/context.ts`、`tool-read.ts` 和 `run-tools.ts`，梳理界面提供上下文、智能体请求模型规划、工具按需读取作品条目、Core 读取本地文件的路径。
5. 用 `sed` 和 `rg -n` 阅读 `tool-edit.ts`、`proposals.ts`、`useProposalCoordinator.ts`、`useLongWorkspaceProposals.ts`、`long-core-commands.ts` 和 `long-workspace-service.ts`，核对修改先形成提案与差异、按审批策略接受、再写入文稿及索引的顺序。
6. 用 `sed` 阅读 `ledger-tools.ts`、`long-project-store/continuity.ts`、`commit-chapter-structured.ts` 和 `longContinuityFinalization.ts`，确认连续性记录在章节正文保存后的提交条件，以及人物状态、历史轨迹和世界观揭露的映射位置。
7. 根据上述调用链写出 Mermaid `sequenceDiagram`：设置作者、界面、长篇智能体、大模型、Core、本地文件六个参与者，用 `loop` 表示设定到正文的循环，用 `alt` 表示人工批准或自动批准，用 `opt` 表示按要求提交连续性账本。
8. 调用 `mcp__codex_app__list_threads`、`read_thread` 找回已绘制的时序图；使用 `knowledge-operation-center` 的 `detect_obsidian.sh` 确认目标知识库，用 `create_note.sh` 写入待审笔记，用 `obsidian.sh read` 回读校验；收到审核与归位指令后，用 `property:set` 更新状态、用 `move` 移入“动态项目 / 虚拟世界”。
9. 为第二张图调用 `functions.exec` 中的 `exec_command`，用 `rg -n` 和 `rg --files` 搜索“智能体团队”“从技能库加载”、子智能体、技能库、素材库及作品绑定相关实现，定位界面组件、契约、运行时和资料库文档。
10. 用 `sed` 阅读 `AgentTeamSettingsPanel.template.html`、`LoadSubagentFromSkillDialog.vue`、`subagent-authoring-tools.ts` 和 `subagent-authoring.ts`，确认“从技能库加载”会读取选中技能正文、生成子智能体系统提示词草稿，确认并保存团队后才生效；这一步是生成时的一次性转写。
11. 用 `sed` 阅读 `subagent-runtime.ts`、`subagent-material-context.test.ts` 和 `short-agent-tools/catalog-tools.ts`，确认主智能体通过 `spawn_subagent` 委派任务，普通子智能体没有 `load_skill`、不能递归委派，但能在允许范围内查询关联素材，并按提示词直接改文档或只交回结论。
12. 用 `sed` 与 `rg -n` 阅读 `README.md`、`skill-and-material-library-structure.md`、`writing-agent-prompts.ts` 和 `builtin-subagents.ts`，确认作品按需绑定技能库与素材库：技能提供写作方法，素材提供参考内容；内置库管理子智能体只在作者明确要求维护库时调用。
13. 根据核对结果写出 Mermaid `flowchart LR`：画出作者、作品、主智能体、团队子智能体、技能库和素材库的运行关系，再单独画出“技能转提示词草稿”和“内置库管理”的两条路径。
14. 用 `knowledge-operation-center` 的 `detect_obsidian.sh`、`obsidian.sh search` 和 `read` 核对目标库及已有时序图，再用 `create_note.sh` 将第二张图直接写入“动态项目 / 虚拟世界”，设置已确认状态，并通过回读和文件信息校验写入结果。
15. 为本次合并调用 `obsidian.sh read` 取回两张 Mermaid 原图，借助 Obsidian 内置的 `mermaid.render` 生成 SVG；通过 `obsidian.sh eval` 的 `createBinary`、`modifyBinary` 保存图片、补齐白色背景和 SVG 的换行标签，并把原始 Mermaid 源码保存在 SVG 元数据中。
16. 用 `view_image`、`sharp` 临时预览和 Playwright 浏览器截图检查两张 SVG 的可读性；再用 `create_note.sh` 新建本页，通过 `obsidian.sh read`、链接检查核对只有两个一级标题、图例下只有两张图片和本序号列表；核验新页完整后清理已合并的两张旧笔记。

17. 调用 `functions.exec` 中的 `exec_command`，用 `git status`、`git ls-files`、`rg` 和 `sed` 检查外层 `heavenly-palace` 与原 `deepwrite` 目录：确认前者尚未跟踪应用，后者有独立的 `.git`、2142 个已跟踪文件和未提交改动；同时找到首页左上角品牌入口、构建入口及两份仍引用旧绝对路径的世界观整理脚本。
18. 用 `view_image` 查看原 `app-icon.png`，用 `sed` 阅读 `LeftSidebar.vue`、`AppIcon.vue`、`WindowFrame.vue`、`index.html` 和品牌样式，确定将可见名称改为“虚拟世界”，图标采用地球与展开书页的组合，并保持项目内部包名及运行协议可用。
19. 调用 `apply_patch` 修改侧栏品牌文字、窗口标题、网页标题和 favicon，新增 `apps/desktop/src/renderer/public/virtual-world-icon.svg`，使 `AppIcon` 的品牌图标引用新 SVG；同步把项目 `AGENTS.md` 的目录示意名改为 `virtual-world`。用 `qlmanage -t` 生成预览，再用 `view_image` 检查图标形状。
20. 用 `ps`、`lsof` 查明旧目录的 Electron 开发进程与 5173 端口，调用 `kill -TERM` 停止进程；用 `mv` 把原子仓库的 `.git` 移入外层仓库的 `.git/deepwrite-legacy.git`，再把 `productivity/tool-library/deepwrite` 改名为 `productivity/tool-library/virtual-world`，并用 `git rev-parse` 核对原提交 `d01d18b` 仍在、应用目录现在归外层 Git 管理。
21. 调用 `apply_patch` 更新 `entertainment/virtual-world/worldbuilding-rebuild/2026-09-27-six-realms/ops/` 下的 `replace-worldbuilding.ts` 和 `update-worldbuilding.ts`，把六处指向旧 `deepwrite` 目录的绝对导入路径改为新目录；用 `rg` 再查旧路径引用。
22. 在新目录调用 `pnpm verify`；首次格式检查发现 `AppIcon.vue` 和两份此前已修改的图片引用工具文件不符合 Prettier 格式，遂用 `prettier --write` 只整理这三个文件，再运行格式、类型、ESLint、进程边界及测试检查。
23. 用外层仓库的 `git add -A` 只暂存 `productivity/tool-library/virtual-world`，排除原目录中与应用无关的临时 HTML 文件 `null`；用 `git diff --cached`、`git status` 检查纳入的 2154 个文件，并核对 `.env.example` 与新增测试没有实际密钥或真实接口凭据。
24. 发现默认并发下完整测试随机触发 5 秒超时后，用 `sysctl`、`vitest --help` 及本地 Vitest 代码确认可通过 `VITEST_MAX_WORKERS` 限制工作进程；设置为 4 后重跑 `pnpm verify`，644 个测试文件、3656 个测试全部通过。
25. 构建阶段的 `check-renderer-build.mjs` 仍硬编码要求 HTML 含“DeepWrite”，用 `sed` 定位后调用 `apply_patch` 改为检查“虚拟世界”标题；重新构建又发现入口 JavaScript 超过原有 1000000 字节预算 18 字节，遂去掉侧栏品牌按钮上与可见文字重复的辅助标签，复测得到 999975 字节并通过构建检查。
26. 用 `VITEST_MAX_WORKERS=4 pnpm verify` 完成最后一轮格式、类型、静态检查、3656 项测试和构建验证；核对暂存内容都在新目录后，在外层仓库创建提交 `0b866ec`，并按项目规范仅为该次提交设置本地提交身份，提交后恢复外层仓库原有的身份配置。
27. 从新目录运行 `pnpm dev` 重启 Electron 开发服务；用 `curl` 确认 `http://127.0.0.1:5173/` 与新 SVG 图标均返回 200，用 `git rev-parse`、`git ls-files` 检查外层仓库管理着 2154 个应用文件。尝试用 `mcp__cua_repl` 核验桌面窗口时遇到 Mac 锁屏，因此只完成服务与资源的可用性检查，未声称完成窗口画面核验。
