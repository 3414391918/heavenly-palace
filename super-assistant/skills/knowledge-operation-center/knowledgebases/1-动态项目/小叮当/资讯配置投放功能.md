# 图例说明

这是一个给小叮当这个产品提供的运营方面的功能，目前市面上像workbuddy、codex这样的产品都有这样的功能。在公司内部，它的作用包括神灯文章推送、吐槽大会报名、新功能引导，活动引流，是增加活跃和留存的策略。未来还会在资讯中心挂签到任务、投稿任务赚积分换模型使用权，这些方面都能带来正向收益。
功能实现就是在小叮当的cloud后台加了一个资讯中心管理的菜单，产品和运营可以在这个菜单里去定制一些消息卡片投放到指定用户人群，支持周期推送，支持上传裁剪图片，定制按钮样式和功能，有跳转到第三方链接的按钮，有跳转到小叮当上指定功能的按钮，还有投票统计的按钮，按钮的点击量还有统计参与用户，这些数据都会实时的展示在资讯中心的管理页。
投放的设计没有使用websocket实时推送，使用websocket也是可以的，我用的是一种简单的方案，运营在后台配置完消息卡片后点投放，数据会进入到数据库，用户启动应用或者切回窗口的时候会触发一个事件，这个事件会去调用接口拉取卡片数据。当然不是用户每次点击操作都会弹出消息卡片，有一张领取记录表来控制消息卡片向用户展示的频次。运营在配置消息卡片的时候会设置一个有效期，投放频次有三种选项，有效期内只投1次，有效期内每天投1次，有效期内每周投1次。小叮当在拉取卡片数据的时候，对于获取到的每张卡片，会向领取记录表中插入1条记录，通过一个周期键来控制插入是否成功，插入成功说明这张卡片是当前周期用户第一次领取，这张卡片就会展示给用户，否则的话卡片不会展示给用户。
有效期内只投一次，周期键就是 发布版本+once标识
有效期内每天一次，周期键就是 发布版本+北京日期
有效期内每周一次，周期键就是 发布版本+ISO年周

# 执行路径

1. **初始化需求和知识记录。** 根据“消息发布和推送”的需求，在“动态项目/小叮当”建立本文，保持“图例说明”和“执行路径”的笔记结构。先把配置投放、持久化和桌面领取的时序图存入同目录 `assets/`，随后陆续补入频次、功能清单、定向推送和互动统计时序图；正文均以 Obsidian 嵌入语法引用，而非把图片内容复制进正文。

2. **确定代码范围与基线。** 从 JoyDesk 仓库与 `feature/202609` 出发，分别定位 Cloud 管理后台 `apps/cloud/web`、Spring Boot 服务 `apps/cloud`、内场 Electron 桌面端 `apps/desk/frontend`。首期在 `codex/feature-20261009-news-center` 开发；后续用户明确要求合入并直接在 `feature/202609` 上迭代。每次修改前检查 Git 状态和 diff，保留无关工作区文件。

3. **逐页核对产品原型。** 使用 Google Chrome 打开 `https://var.jd.com/#/preview?id=69175cc4-61f7-4b5a-9e8c-f47b56cf22c2`，对照用户截图检查问号菜单、“资讯中心”、编辑弹窗、首页实时预览、发布确认、按钮/气泡、投放频次和卡片轮播。特别核实首页及发布确认页的卡片都能横向拖拽调整顺序；首版范围先做全员推送和卡片展示，按钮实际跳转、定向、统计后续增量实现。

4. **整理实现合同。** 在 `harness/features/news-center-delivery-20261009/` 记录计划、接口与数据不变量、实施进度和评审结论。明确 Cloud MySQL 是配置、发布快照、顺序、领取记录的权威；桌面端不保存投放配置。接口按“管理端写入、用户端读取/领取”分开，先确认系统管理员权限、租户和登录用户边界。

5. **建设首批持久化表。** 新增 `news_center_card`、`news_center_claim`、`news_center_order_lock`，并写 Cloud 菜单定义及权限。`draft_json` 与 `published_json` 分离：保存草稿不改线上内容，发布才替换快照；`version` 与全局排序版本拒绝陈旧写入；`publish_version` 参与自动弹窗去重。迁移在 `V20261009130__news_center_delivery.sql`，预发未自动跑 Flyway 时给出 `apps/cloud/scripts/mysql/20261009_news_center_delivery_pre.sql`，由用户在预发库执行。

6. **实现配置、发布与拖拽。** `NewsCenterService`、管理 API 和 Cloud Web 页面提供新建、编辑、复制、保存草稿、发布、移入草稿、结束投放和顺序提交。管理首页与确认页均使用拖拽组件；提交顺序时要求完整卡片 ID 排列，服务端在事务中校验版本后写入，避免并发管理员互相覆盖。新增配置首次投放后来改成默认排在弹窗 1。

7. **实现内场桌面展示与领取。** 问号菜单加入“资讯中心”，`MenuColumn.vue` 在用户主动打开时调 `/api/news-center/active`，在桌面启动/窗口重新获得焦点时调 `/api/news-center/claim`；`NewsCenterCarousel.vue` 按 Cloud 顺序展示卡片。主动查看不消耗自动弹窗次数，Cloud 不可达时保留入口并给出重试态。仅内场 `desk` edition 运行该链路。

8. **固定自动推送频次。** Cloud 只返回状态为 `PUBLISHED` 且北京时间处于上线/下线日期内的快照；自动领取用 `(user_pin,card_id,period_key)` 唯一键去重。周期键包含发布版本，并按 `ONCE`、北京时间自然日、ISO 自然周区分“仅一次、每天一次、每周一次”；重新发布使发布版本递增。对应逻辑和边界见 `NewsCenterService.periodKey` 及频次时序图。

9. **本地启动 Cloud 预发联调。** 在本机以开发进程连接预发 RDS，关闭不适合本机运行的自动迁移、业务定时任务和本地 Temporal，使用健康接口、管理接口和预发库只读查询检查链路。建表前新接口因缺表失败；用户执行首批 SQL 后，在原 8081 进程位置重新启动服务，管理页、列表、排序版本和客户端有效资讯接口恢复。本地桌面端也连接同一个本地 Cloud 实例，避免“后台写本地 8081、桌面读远端预发”的错位。

10. **首轮端到端验证并清理测试数据。** 通过本地后台发布临时全员卡片，验证管理端拖拽顺序反映到客户端接口与桌面轮播；再次领取返回空，证明一次性去重。核对卡片与领取记录 ID 后清理联调数据，并恢复桌面端原 Cloud 地址。首期提交 `f21e89a205` 记录了 Cloud 11 项、Desk 56 项定向测试、Cloud Web 构建和本地投放/领取/配图联调；当时远端预发 Cloud 尚未部署新 API。

11. **排查“复制其他配置点不了”和布局偏差。** 在空配置库中，前端把复制入口直接禁用，且复制已有配置时沿用编辑 ID，保存会误改原记录。检查列表接口确认不是权限失败后，改为入口始终可打开、空态给说明；复制时深拷贝配置、清空编辑 ID 并生成独立草稿。编辑界面按原型改成居中弹窗、顶部操作、左右分栏和右侧实时预览；用回归测试、本地 8081 页面及临时草稿验证，再清理临时记录。

12. **排查蓝色按钮预览变黑与必填星号。** 核对已发布 JSON 后确认按钮颜色仍为 `blue`；浏览器计算样式显示 Cloud 的共享 `--primary` 实际为深色，故改用明确的蓝到青渐变并同步桌面样式。必填 `*` 原先作为普通文字继承黑色，改用表单必填标记使其显示红色。旧浏览器标签页仍加载旧静态资源时先保存草稿，再刷新查看新构建，避免把缓存现象当成保存失败。

13. **接入并诊断图片上传。** 原上传链路使用的 OSS 内网端点在本地超时；检索项目已有对象存储接入后，`NewsCenterImageService` 改用 `JdcloudOssService` 上传 JPG/PNG，限制 5 MB 并检查文件签名。卡片保存稳定的 Cloud 图片路径，读取时服务端签发短期对象存储访问地址；补京东云配置的图片路径白名单。本地曾验证上传后 Cloud 返回 302、签名地址返回 200 和正确图片类型，测试对象随后清理。

14. **处理本地域名、认证与进程错位。** `local.jd.com:8081`、`127.0.0.1:8081` 与 `xdd-cloud-pre.jd.com` 是不同请求目标；HTTP 本地域名不会携带仅供 HTTPS 发送的 `Secure` SSO Cookie，Chrome 已登录预发页也不代表本地 API 自动鉴权。联调时核对域名解析、请求地址、Cookie/认证代理和后台 8081 进程实际加载的代码。用户要求后续功能改动直接重启原进程，不再叠开第二个服务进程。

15. **把写死的目标功能改成桌面端上报。** `newsCenterActions.ts` 在桌面端集中维护稳定功能 ID、名称和本地打开函数；管理员桌面启动或窗口重新获得焦点时先核验系统管理员身份，再把 `{id,label}` 与技术版本上报 Cloud。Cloud 持久化到 `news_center_feature_catalog`，管理平台读取最新清单；不接受客户端上报可执行路由或命令。预发缺表时管理页显示“功能清单暂不可用”；用户执行 `20261012_news_center_feature_catalog_pre.sql` 后，原位更新 8081 进程，重新核验功能下拉。相关提交为 `1edaba6385`。

16. **实现两类按钮动作。** “查看详情”只接受 HTTPS 链接，由桌面端打开系统浏览器；“立即体验”只保存功能 ID，Desk 从本地功能表找到对应导航动作，不由 Cloud 决定内部路由。“项目”打开当前项目工作台，无当前项目给出提示；未来新增功能只需在桌面功能表添加稳定 ID 和打开函数，并由管理员新版桌面再次上报。未知 ID 给出升级提示。

17. **增加定向推送并核实数据源。** 在 Cloud 既有用户组接口、`user_group`/`user_group_member` 与 IAM 组织树、部门模糊搜索中确认可取自定义人群和部门；管理页可选版本规则、多个用户组和多个部门。三种维度及同维度多条件均按“命中任一”并集计算；部门包括下级。Cloud 在发布时校验组与部门并在快照中绑定租户，在 `active`/`claim` 读取时按当前登录用户匹配，未命中不写领取记录；返回桌面的卡片剔除内部受众编码。相关提交为 `27fb2a18bb`。

18. **修正版本口径与比较。** 管理页提示开发/预发用日期技术版本（如 `2026.10.9-beta.2`），正式打包版用左上角用户可见版本（如 `5.0.0`）。未打包开发版虽然界面显示 `Dev`，筛选仍取 `package.json` 的技术版本；功能清单上报继续用技术版本。版本比较逐段按数字，支持预发布后缀；多条版本条件为并集。定向推送评审还发现跨租户部门编码误命中和极长数字后缀比较异常，分别用租户绑定与任意精度数字比较修复，补了回归测试。

19. **定义统计语义并落表。** 按用户最终决定，以卡片 ID 累计到结束投放：同一 ERP 对同一卡片只保存最新 `JOIN`/`DECLINE` 选择，来回改选更新原记录；链接和客户端功能只按按钮位置、动作类型原子累计点击数，不保存 ERP。新表是 `news_center_participation`、`news_center_click_count`；提供 Flyway 迁移与等价预发 SQL，用户执行了预发建表脚本。再次发布沿用卡片 ID，因此统计不清零；结束投放后拒绝新增互动，历史仍可查。

20. **调整“参与统计”的配置方式。** 最初把参与动作放进单个按钮的“点击后执行”选项，与用户期望不符；随后在“添加按钮”旁加独立“参与统计”，一次创建左侧固定文案“暂不参与”和右侧固定文案“愿意参与”。这两个按钮不显示“点击后执行”，仍可各自设颜色和气泡；删除时整组移除。发布校验拒绝单个参与按钮、混入普通动作、换序或改文案。

21. **排查气泡颜色无法选择。** 浏览器可点到颜色，表单也保存了颜色，但选中态原先还要求气泡文字非空，导致“先选颜色”看起来没反应。改为仅以 `bubbleColor` 判断色块选中，“无气泡”同时清空文字和颜色；输入气泡文字而未选色时默认红色。用本地 8081 页面覆盖先选颜色、先填文字和清空三种路径。

22. **实现互动接口和兼容保护。** Desk 点击参与按钮时上报卡片 ID、发布版本、按钮位置与客户端版本，Cloud 以当前已发布快照校验登录、日期、受众、发布版本和按钮动作后写入；Desk 回显当前选择且允许改选。普通按钮先上报点击，再执行既有链接/功能动作；统计失败不阻断目标打开。Cloud 管理页在每张卡片内显示累计统计，支持分页搜索参与/不参与 ERP；用户端只能读取本人选择。提交 `909c3e79b1` 的历史验证包括 Cloud 18 项 JUnit、Desk 46 项 Vitest、Cloud Web 7 项 Node 测试和构建。

23. **复审旧客户端与并发问题。** 旧 Desk 不认识 `PARTICIPATION`，直接下发会使整批卡片解析失败；新 Desk 因此声明 `news-participation-v1`，Cloud 在写领取记录之前过滤旧端不支持的参与卡片。ERP 明细快速切换卡片/关键词时仅接受最新请求；互动写入先做受众等慢查询，再短暂锁定卡片校验状态与版本。旧 Cloud 回滚也不能直接读取含新枚举的 JSON，回滚约束保存在 `harness/features/news-center-delivery-20261009/02-contract.md`。

24. **解决“下一步点不了”的校验反馈。** 发布前校验要求跳转链接为 HTTPS；用户新建配置时可先不填链接并保存草稿，但点击“下一步”发布前必须补全。管理页把错误提示放在编辑弹窗内并明确指出按钮序号与 HTTPS 约束，避免无反馈地停在原页。

25. **合并和核对预发部署。** 互动统计阶段先提交开发分支，再合入 `feature/202609`（合并提交 `5e77c4cd34`）。Cloud 预发页面曾打不开或仍显示旧提交；排查时在“系统运维工具 → 环境信息”读取运行 SHA、启动时间和健康状态，而不是只看本地/远端分支。桌面构建流水线进行中时曾等待，不中断该任务；Cloud 的重新部署通过预发运维入口进行，部署后用 `/system/news-center` 实际页面复核。服务器部署目标始终是 `xdd-cloud-pre.jd.com` 预发，不把本地 8081 当成服务器部署。
